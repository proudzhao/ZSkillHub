# 架构时序规则（UML Sequence 语义）

## 语义定位

本 skill 画的是**架构/组件级时序**：参与者（Actor、服务、网关、存储、外部系统）之间按时间顺序的消息。

- 是：谁在何时调用谁、同步/异步、返回什么
- 不是：数据存哪里的全景（用 arch-dataflow-diagram）、完整 Java 调用树（用 method-flow）、UI 点击步骤清单

## 粒度

| 级别 | 参与者示例 | 何时使用 |
|------|------------|----------|
| 默认：架构/组件 | 用户、网关、订单服务、库存服务、支付网关、订单库 | 常规需求/设计说明 |
| 细化：类/方法 | `OrderService.create`、`InventoryClient.deduct` | 用户指定，或某跳对理解场景至关重要 |

细化时：只展开关键生命线，其余仍保持组件级，避免一张图变成调用树。

## 场景策略

| 策略 | 规则 |
|------|------|
| 默认 | **仅主成功路径** 一张图 |
| 按需 | 用户明确要求时另出：异常、超时重试、补偿、纯异步回调等，**一场景一图** |
| 主成功图内 | 尽量少用 `alt`；非关键分支用文字「待确认/见异常图」而非塞进主图 |

## 消息约定

1. 每条消息有短标签：动词 + 关键数据（如 `创建订单(sku, qty)`），禁止无意义的 `call`/`return`。
2. 同步用 `->>`，返回用 `-->>`，异步用 `-)` 且标签加 `异步:` 前缀（可选但推荐）。
3. 自调用仅在该步骤对理解有价值时保留。
4. 参与者从左到右：发起方 → 本系统组件（调用顺序）→ 外部系统/存储。
5. 参与者建议不超过 8 个；过多则合并角色或拆子时序。

## 校验清单（输出前必过）

- [ ] 明确场景名，且默认仅为主成功（除非用户另有要求）
- [ ] 参与者均为架构/组件级，或已按用户要求局部细化
- [ ] 消息自上而下时间有序，标签非空
- [ ] 同步调用若有业务结果，应有返回消息（或在请求标签内写清返回语义）
- [ ] 异步与同步箭头类型正确
- [ ] 未把数据流图元素（加工编号、DFD 存储符号）混进时序图
- [ ] Mermaid 中文已加双引号
- [ ] 参与者数量可控（约 <=8）

## 标准溯源（简）

对齐 UML 2 Sequence / Interaction（生命线、消息、组合片段）与 BABOK Sequence Diagrams 的场景交互用法。Mermaid 不追求 100% UML 图形完备（激活条等可省略），以工程可读性为准。
