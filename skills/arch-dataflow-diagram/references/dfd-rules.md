# 架构数据流规则（Gane-Sarson 语义）

## 语义定位

本 skill 画的是**架构数据流**：关注系统边界、外部系统、内部加工（服务/模块/作业）与数据存储之间**数据如何移动**。

- 是：谁产生数据、谁消费、落哪里、异步通道是什么
- 不是：控制流（if/循环）、UI 点击步骤、方法级调用栈、精确时序

命名上可保留「DFD / Level 0/1」便于沟通，但元素解释按架构语境（加工≈服务/模块，存储≈DB/Cache/MQ 等）。

## 四类元素

| 元素 | 命名 | 要点 |
|------|------|------|
| 外部实体 | 名词（系统名/角色） | 边界外；可同时是源与宿 |
| 加工 | `编号 + 动词短语`（如 `1.0 校验并下单`） | 改变或路由数据；必须有入有出 |
| 数据存储 | `D编号 + 名词`（如 `D1 订单库`） | 逻辑存放点，可对应物理库表/Topic/文件 |
| 数据流 | 名词短语（如 `订单创建请求`） | 箭头表示数据移动方向与内容 |

## 分层

| 层级 | 内容 | 何时画 |
|------|------|--------|
| Level 0 上下文 | 整个系统=一个加工；只连外部实体与跨边界数据流 | **默认必出** |
| Level 1 | 分解为 3–7 个主加工 + 内部存储与流 | **默认必出** |
| Level 2 | 对某一个 Level 1 加工再分解 | 单加工步骤多、或用户明确要求 |

**平衡**：Level 0 与外部实体之间的数据流集合，应与 Level 1 中进出系统边界的数据流一致（可合并/拆分命名，但语义要对得上）。

## 硬规则

1. 每个加工至少一条入流、一条出流。
2. 外部实体与数据存储**不得直连**；必须经加工。
3. 数据流必须有标签（禁止无标签箭头）。
4. 同一张图内编号唯一：加工 `0.0` / `1.0`…，存储 `D1`…
5. 不把纯控制信号画成数据流；若仅有触发无载荷，标为 `触发信号` 并在字典中说明，或改用时序图。
6. MQ/Topic：既可画成**存储**（持久队列），也可画成**带标签的异步数据流**；同文档内选一种并保持一致，推荐：持久化队列用存储 `D_MQ_xxx`，瞬时点对点用流标签注明「异步」。

## 校验清单（输出前必过）

- [ ] Level 0 仅一个系统加工，且外部实体齐全
- [ ] Level 1 加工数量大致 3–7（过多则合并或下钻）
- [ ] 无「外部实体 ↔ 存储」直连
- [ ] 每个加工、每个被使用的存储有合理入/出（只写库注明「写入」；只读注明「读取」）
- [ ] 所有数据流有中文/英文标签
- [ ] Level 0/1 边界流平衡
- [ ] 未把时序/分支控制画进图
- [ ] Mermaid 中文标签已加双引号
