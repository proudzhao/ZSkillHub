# 文档模板

本地 Markdown 与飞书正文共用同一结构。飞书创建时：`title` 用文档标题，正文从 `##` 开始，**不要**再写与 title 相同的一级标题。

## 正文结构

```markdown
## 概述

- **系统**：{系统名称}
- **范围**：{边界一句话}
- **层级**：Level 0 + Level 1（如有 Level 2 注明针对哪个加工）
- **符号**：Gane-Sarson 语义（Mermaid 近似）

## Level 0 上下文图

{mermaid 代码块}

## Level 1 架构数据流

{mermaid 代码块}

## 元素字典

### 外部实体

| ID | 名称 | 说明 |
|----|------|------|
| E1 | … | … |

### 加工

| ID | 名称 | 说明 | 所在层级 |
|----|------|------|----------|
| 0.0 | … | 系统整体 | L0 |
| 1.0 | … | … | L1 |

### 数据存储

| ID | 名称 | 类型 | 说明 |
|----|------|------|------|
| D1 | … | DB/Cache/MQ/文件 | … |

### 主要数据流

| 名称 | 从 | 到 | 说明 |
|------|----|----|------|
| … | E1 | 1.0 | … |

## 待确认

- {未知边界、未证实的存储或流}
```

若有 Level 2：在 Level 1 后增加 `## Level 2 — {加工名}` 小节，结构同 Level 1（图 + 必要时补充字典行）。

## 飞书追加模式

用户指定已有文档时，用 `update-doc` `append`，追加内容从 `## 架构数据流 — {系统名}` 或用户指定的章节标题开始，避免与原文一级结构冲突。可先加一条分割说明：

```markdown
## 架构数据流 — {系统名}

> 由 arch-dataflow-diagram 生成
```

其后接上述「概述」起的各节（概述可用 `###` 若需降低标题层级）。

## 本地文件

- 默认路径：`docs/dataflow/{slug}-数据流.md`
- `{slug}`：系统名拼音或英文短名，小写连字符
